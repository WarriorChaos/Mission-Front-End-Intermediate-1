1. GAMBARAN PROJECT
====================================================================

Project ini adalah aplikasi frontend bernama videobelajar. Aplikasi ini
menampilkan platform belajar video dengan beberapa halaman utama:

- Homepage atau beranda.
- Halaman login.
- Halaman register.
- Header dan footer pada halaman utama.
- Kartu course yang dapat digunakan ulang.
- Filter kategori course.
- Authentication sederhana untuk simulasi login.
- Perlindungan route agar homepage hanya dapat dibuka setelah login.

Authentication pada project ini belum menggunakan backend atau database.
Artinya, email dan password belum benar-benar diverifikasi ke server.
Login dianggap berhasil selama email dan password tidak kosong. Ini cocok
untuk latihan frontend, tetapi belum cukup untuk aplikasi production.

URL saat menjalankan project:

- Homepage: http://localhost:5173/
- Login: http://localhost:5173/login
- Register: http://localhost:5173/register

Jika port 5173 sedang digunakan oleh aplikasi lain, Vite otomatis memilih
port lain, misalnya:

- http://localhost:5174/

Jika belum login lalu membuka homepage, aplikasi mengarahkan pengguna ke:

- http://localhost:5174/login

3. MEMAHAMI REACT SECARA SEDERHANA
====================================================================

React adalah library JavaScript untuk membuat user interface. Cara berpikir
React berbeda dari HTML biasa. Pada HTML biasa, kita cenderung menulis satu
file besar. Pada React, tampilan dibagi menjadi bagian-bagian kecil yang
disebut component.

Contoh component sederhana:

    function Greeting() {
      return <h1>Halo</h1>;
    }

Component adalah function yang mengembalikan JSX.

JSX adalah syntax yang terlihat seperti HTML, tetapi ditulis di dalam
JavaScript. Contoh:

    const title = 'Belajar React';

    function App() {
      return <h1>{title}</h1>;
    }

Tanda kurung kurawal digunakan untuk memasukkan nilai JavaScript ke JSX.

Aturan dasar component React:

- Nama component harus diawali huruf besar.
- Component mengembalikan satu parent element, atau menggunakan fragment.
- Attribute HTML ditulis dalam format camelCase, misalnya className.
- JavaScript di dalam JSX ditulis menggunakan kurung kurawal.
- Component dapat menerima data dari parent melalui props.

Contoh fragment:

    function Menu() {
      return (
        <>
          <a href="/">Home</a>
          <a href="/about">About</a>
        </>
      );
    }

4. MEMAHAMI VITE
====================================================================

Vite membantu menjalankan dan membangun project React.

Saat menjalankan:

    npm run dev

Vite membuka server lokal. Setiap perubahan file akan dikirim ke browser
menggunakan HMR atau Hot Module Replacement. Dengan HMR, perubahan kode
biasanya langsung terlihat tanpa reload manual.

Saat menjalankan:

    npm run build

Vite melakukan beberapa hal:

- Mengubah JSX dan JavaScript menjadi bundle.
- Memproses CSS.
- Mengoptimalkan asset.
- Menghasilkan folder dist.
- Memeriksa apakah ada import yang tidak ditemukan.

Contoh hasil build yang berhasil:

    vite building client environment for production...
    53 modules transformed.
    built in ...

Jika build gagal, jangan langsung menebak. Baca nama file dan pesan error.
Biasanya pesan tersebut menunjukkan lokasi masalah.

7. KONSEP COMPONENT DAN PROPS
====================================================================

Props adalah data yang dikirim dari parent component ke child component.
Props membuat component lebih fleksibel dan reusable.

Contoh Button:

    function Button({ children, variant = 'primary', onClick }) {
      return (
        <button className={variant} onClick={onClick}>
          {children}
        </button>
      );
    }

Pemakaian:

    <Button variant="secondary" onClick={handleClick}>
      Simpan
    </Button>

Pada contoh tersebut:

- children berisi teks Simpan.
- variant berisi secondary.
- onClick berisi function handleClick.

Contoh Input controlled:

    <Input
      label="Email"
      value={email}
      onChange={(event) => setEmail(event.target.value)}
    />

Component Input tidak menyimpan nilai sendiri. Nilainya dikontrol oleh
parent melalui value dan onChange. Pola ini disebut controlled component.

Keuntungan component reusable:

- Mengurangi duplikasi kode.
- Perubahan dapat dilakukan di satu tempat.
- Tampilan lebih konsisten.
- Logic lebih mudah dipelajari dan diuji.

8. KONSEP STATE DAN CONTROLLED INPUT
====================================================================

State adalah data yang dapat berubah dan ketika berubah menyebabkan React
melakukan render ulang.

Contoh:

    import { useState } from 'react';

    const [email, setEmail] = useState('');

- email adalah nilai state.
- setEmail adalah function untuk mengubah state.
- '' adalah nilai awal.

Input login menggunakan pola berikut:

    <input
      value={email}
      onChange={(event) => setEmail(event.target.value)}
    />

Urutan kejadiannya:

1. User mengetik.
2. Browser menghasilkan event.
3. onChange dijalankan.
4. setEmail menyimpan nilai baru.
5. React melakukan render ulang.
6. value input menampilkan nilai state terbaru.

Untuk form register, seluruh nilai disimpan dalam satu object:

    const [formData, setFormData] = useState({
      fullName: '',
      email: '',
      phone: '',
      password: '',
      confirmPassword: ''
    });

Handler-nya:

    const handleChange = (event) => {
      const { name, value } = event.target;
      setFormData((previous) => ({
        ...previous,
        [name]: value
      }));
    };

Bagian [name] disebut computed property. Jika name bernilai email, maka
property email yang diperbarui.

Karena itu setiap input harus memiliki name yang benar:

    <input name="email" />

9. KONSEP ROUTING
====================================================================

React Router memungkinkan aplikasi memiliki beberapa URL dalam satu SPA.
SPA berarti Single Page Application. Browser tidak perlu memuat ulang
seluruh dokumen setiap kali berpindah route.

Di App.jsx, route utama saat ini adalah:

    <Route
      path="/"
      element={<ProtectedRoute element={<HomePage />} />}
    />

    <Route path="/login" element={<LoginPage />} />
    <Route path="/register" element={<RegisterPage />} />

Komponen penting React Router:

- BrowserRouter atau Router:
  Mengaktifkan sistem routing.

- Routes:
  Container untuk kumpulan route.

- Route:
  Menghubungkan path dengan element.

- Link:
  Berpindah halaman tanpa reload penuh.

- Navigate:
  Melakukan redirect dari dalam component.

- useNavigate:
  Mengubah route melalui function JavaScript.

Contoh:

    const navigate = useNavigate();
    navigate('/login');

13. PEMBUATAN AUTHCONTEXT
====================================================================

Context digunakan ketika banyak component membutuhkan data yang sama.
Daripada mengirim props melewati banyak level component, kita menyediakan
nilai dari provider.

File yang berhubungan:

- src/contexts/AuthContext.jsx
- src/contexts/AuthContextValue.js
- src/contexts/useAuth.js

AuthContextValue.js membuat context:

    import { createContext } from 'react';

    export const AuthContext = createContext();

AuthProvider membungkus seluruh route pada App.jsx:

    <AuthProvider>
      <Routes>
        ...
      </Routes>
    </AuthProvider>

Nilai yang disediakan provider:

- user
- isAuthenticated
- isLoading
- login
- register
- logout

Component yang membutuhkan auth menggunakan custom hook:

    const { user, isAuthenticated, logout } = useAuth();

AuthProvider memiliki function login:

    const login = (email, password) => {
      if (email && password) {
        const userData = {
          email,
          name: email.split('@')[0],
          loginTime: new Date().toISOString()
        };
        setUser(userData);
        localStorage.setItem(
          'videobelajar_user',
          JSON.stringify(userData)
        );
        return true;
      }
      return false;
    };

Catatan: kode ini adalah simulasi. Password tidak disimpan dan belum ada
verifikasi ke server.

====================================================================
14. PENYIMPANAN LOGIN DENGAN LOCALSTORAGE
====================================================================

localStorage adalah penyimpanan sederhana pada browser dengan format key dan
value string.

Menyimpan object harus menggunakan JSON.stringify:

    localStorage.setItem(
      'videobelajar_user',
      JSON.stringify(userData)
    );

Membaca kembali harus menggunakan JSON.parse:

    const storedUser = localStorage.getItem('videobelajar_user');
    const user = storedUser ? JSON.parse(storedUser) : null;

Pada AuthContext, getStoredUser dijalankan sebagai lazy initializer:

    const [user, setUser] = useState(getStoredUser);

Artinya function getStoredUser dijalankan untuk mendapatkan nilai awal state.

Logout menghapus state React dan localStorage:

    const logout = () => {
      setUser(null);
      localStorage.removeItem('videobelajar_user');
    };

Cara memeriksa localStorage secara manual:

1. Buka browser.
2. Tekan F12.
3. Buka tab Application atau Storage.
4. Pilih Local Storage.
5. Pilih alamat localhost.
6. Cari key videobelajar_user.

Jika key ada, browser akan menganggap user masih login ketika halaman dibuka
kembali. Jika key dihapus, user harus login lagi.

15. PROTECTEDROUTE
====================================================================

ProtectedRoute digunakan untuk membatasi homepage.

Logikanya:

1. Ambil isAuthenticated dari useAuth.
2. Jika sedang loading, tampilkan Loading.
3. Jika tidak authenticated, redirect ke /login.
4. Jika authenticated, tampilkan element yang diberikan.

Kode sederhananya:

    export default function ProtectedRoute({ element }) {
      const { isAuthenticated, isLoading } = useAuth();

      if (isLoading) {
        return <div>Loading...</div>;
      }

      if (!isAuthenticated) {
        return <Navigate to="/login" replace />;
      }

      return element;
    }

Prop element berisi HomePage:

    <ProtectedRoute element={<HomePage />} />

replace digunakan supaya redirect tidak menambah history entry yang tidak
perlu. Dengan begitu tombol Back browser tidak terus-menerus mengembalikan
user ke route yang seharusnya tidak dapat dibuka.

16. UPDATE HEADER DAN LOGOUT
====================================================================

Header sekarang membaca auth state.

Jika belum login, Header menampilkan:

- Masuk.
- Daftar.

Jika sudah login, Header menampilkan:

- Beranda.
- Nama user.
- Logout.

Saat logout:

1. logout() menghapus user dari React state.
2. logout() menghapus videobelajar_user dari localStorage.
3. navigate('/login') mengarahkan user ke halaman login.

Contoh pola handler:

    const handleLogout = () => {
      logout();
      navigate('/login');
    };

17. BUG FORM REGISTER DAN CARA MENEMUKAN PENYEBABNYA
====================================================================

Bug yang ditemukan:

- Field nomor handphone terlihat terisi.
- Beberapa field lain diketik.
- Saat submit, muncul pesan Semua field harus diisi.

Cara investigasi:

1. Membaca pesan error pada browser.
2. Membaca handler handleChange pada RegisterPage.
3. Membandingkan name input dengan property formData.
4. Membaca component reusable Input dan PasswordInput.
5. Menemukan bahwa prop name diterima oleh RegisterPage, tetapi tidak
   diteruskan oleh component reusable ke elemen input HTML.

Sebelum diperbaiki, Input menerima prop seperti ini:

    export default function Input({
      label,
      value,
      onChange,
      required = false
    }) {
      ...
    }

Walaupun RegisterPage mengirim name="fullName", component Input tidak
mengambil prop name. Akibatnya elemen HTML tidak memiliki name.

Perbaikan:

    export default function Input({
      label,
      value,
      onChange,
      name,
      required = false
    }) {
      return (
        <input
          value={value}
          onChange={onChange}
          name={name}
        />
      );
    }

Perbaikan yang sama dilakukan pada PasswordInput.

Pelajaran penting:

- Jangan hanya memeriksa page parent.
- Saat component reusable digunakan, periksa apakah props benar-benar
  diteruskan sampai elemen HTML.
- Jika handler menggunakan event.target.name, pastikan attribute name ada.
- Controlled input membutuhkan value, onChange, dan identitas field yang
  konsisten.

18. MASALAH IMPORT PATH
====================================================================

Error yang ditemukan saat build:

    Could not resolve '../contexts/AuthContext'

File ProtectedRoute berada di:

    src/components/common/ProtectedRoute/ProtectedRoute.jsx

Context berada di:

    src/contexts/AuthContext.jsx

Dari folder ProtectedRoute, harus naik tiga tingkat:

- ../ keluar dari ProtectedRoute.
- ../../ keluar dari common.
- ../../../ keluar dari components dan kembali ke src.

Import yang benar untuk AuthContext:

    import { AuthProvider } from '../../../contexts/AuthContext';

Setelah hook dipisahkan ke file useAuth.js, import yang digunakan component
adalah:

    import { useAuth } from '../../../contexts/useAuth';

Untuk menentukan relative path secara manual:

1. Tulis lokasi file yang sedang mengimport.
2. Tulis lokasi file tujuan.
3. Hitung berapa kali harus naik menggunakan ../.
4. Tambahkan folder tujuan dan nama file.
5. Jalankan npm run build untuk memverifikasi.

Build berhasil setelah import path diperbaiki.

19. MASALAH HMR DAN FAST REFRESH
====================================================================

Saat export useAuth dipindahkan dari AuthContext.jsx, dev server lama sempat
menampilkan error:

    The requested module ... AuthContext.jsx does not provide an export
    named 'useAuth'

Penyebabnya adalah HMR masih menyimpan module state dari versi sebelumnya.
Selain itu, Fast Refresh memiliki aturan bahwa file component sebaiknya hanya
mengekspor component. AuthContext.jsx mengekspor AuthProvider dan useAuth
sekaligus, sehingga ESLint memberi warning/error Fast Refresh.

Solusinya:

- AuthContext.jsx hanya mengekspor AuthProvider.
- AuthContextValue.js mengekspor AuthContext.
- useAuth.js mengekspor custom hook useAuth.
- Semua import useAuth diperbarui.
- Dev server di-restart jika HMR sudah dalam keadaan tidak konsisten.

Jika error module tetap terlihat setelah kode sudah benar:

1. Hentikan dev server dengan Ctrl+C.
2. Jalankan npm run dev lagi.
3. Buka URL baru yang ditampilkan Vite.
4. Lakukan hard refresh browser dengan Ctrl+Shift+R.

Error dari HMR lama tidak selalu berarti source code versi terbaru masih
salah. Bedakan error lama di terminal dengan hasil build terbaru.

21. PANDUAN DEBUGGING MANUAL
====================================================================

Debugging berarti mencari penyebab masalah secara sistematis. Jangan mulai
dengan mengubah banyak file sekaligus. Ubah satu hal, lalu test ulang.

A. Debugging melalui browser Console

1. Buka aplikasi.
2. Tekan F12.
3. Pilih tab Console.
4. Baca error berwarna merah.
5. Klik file dan nomor baris pada error jika tersedia.

Contoh error import:

    Failed to resolve import

Fokus periksa path import dan apakah file benar-benar ada.

Contoh error React:

    useAuth must be used within AuthProvider

Artinya component yang memanggil useAuth tidak berada di bawah AuthProvider.
Periksa struktur App.jsx.

B. Debugging melalui Network

Gunakan tab Network untuk memeriksa:

- Request gambar gagal.
- File JavaScript gagal dimuat.
- Status HTTP 404.
- Request API gagal.

Klik request bermasalah dan periksa URL, status, serta response.

C. Debugging dengan console.log

Untuk memeriksa nilai form:

    console.log('formData:', formData);

Untuk memeriksa event:

    console.log('name:', event.target.name);
    console.log('value:', event.target.value);

Untuk memeriksa auth:

    console.log('user:', user);
    console.log('isAuthenticated:', isAuthenticated);

Setelah masalah ditemukan, hapus console.log yang tidak dibutuhkan agar
console tetap bersih.

D. Debugging dengan React DevTools

React DevTools dapat memperlihatkan:

- Component tree.
- Props.
- State.
- Context.
- Component yang melakukan render.

Jika component tidak menerima props yang diharapkan, periksa component parent
dan child secara berurutan.

23. TROUBLESHOOTING ERROR UMUM
====================================================================

Error: Port 5173 is in use

Penyebab: ada proses Vite lain yang memakai port tersebut.

Solusi:

- Gunakan URL port lain yang ditampilkan terminal, misalnya 5174.
- Hentikan proses Vite lama jika tidak dibutuhkan.
- Jangan menjalankan banyak dev server tanpa alasan.

Error: Failed to resolve import

Penyebab: path salah, nama file salah, atau file belum dibuat.

Solusi:

- Periksa path relatif.
- Periksa huruf besar dan kecil.
- Periksa ekstensi file.
- Jalankan npm run build.

Error: useAuth must be used within AuthProvider

Penyebab: component memanggil useAuth di luar provider.

Solusi:

- Pastikan AuthProvider membungkus Routes.
- Pastikan component berada di dalam tree provider.
- Periksa import AuthContext yang digunakan oleh provider dan hook.

Error: Semua field harus diisi padahal field terlihat terisi

Penyebab umum:

- name input tidak ada.
- name tidak sesuai property state.
- onChange tidak diteruskan.
- value salah.
- state object di-update dengan key yang salah.

Solusi:

- Periksa event.target.name dan event.target.value.
- Tambahkan console.log sementara.
- Periksa component reusable Input.

Error: requested module does not provide an export named ...

Penyebab: file importer meminta export yang tidak lagi tersedia.

Solusi:

- Cari semua import nama tersebut.
- Pastikan file tujuan benar-benar mengekspor nama tersebut.
- Restart dev server jika error hanya muncul setelah perubahan besar.

Error: lint set-state-in-effect

Penyebab: setState dipanggil langsung dalam effect saat inisialisasi.

Solusi pada kasus ini: gunakan lazy initializer useState untuk membaca
localStorage sejak nilai awal state.

Error: gambar tidak tampil

Penyebab mungkin:

- URL gambar salah.
- Internet tidak tersedia.
- Request diblokir proxy atau browser.
- Asset lokal tidak berada di folder yang benar.

Solusi: periksa tab Network dan gunakan asset lokal bila diperlukan.
